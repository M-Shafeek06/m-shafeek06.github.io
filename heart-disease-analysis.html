02 — ANALYTICAL CONTEXT & OBJECTIVE

Explore survival outcomes and health-related patterns across age groups and gender.

The project uses an interactive Power BI report to present outcome counts, survival-rate comparisons and selected health indicators in a single dashboard view.

THE ANALYTICAL FOCUS

Healthcare records need clear comparative views.

The dashboard brings together survival and death counts, age-group comparisons and selected indicators including ejection fraction, serum creatinine, smoking, high blood pressure, diabetes and anaemia. These visuals support exploration of patterns represented in the dataset; they are not clinical diagnosis or causal evidence.

THE PROJECT OBJECTIVE

Build an interactive healthcare analysis dashboard.

Present the overall outcome summary and allow users to compare the displayed measures across age groups and gender selections using Power BI visuals and report controls.

03 — REPORT STRUCTURE

A single Power BI report organized around outcome, demographic and indicator views.

The public repository contains the Power BI dashboard file and four PNG images: a portfolio overview visual and three dashboard screenshots. The structure below describes the visible report; the repository does not document a separate ETL pipeline or underlying data model.

Dashboard summary

Four KPI cards display average survival age, survival rate, total survivors and total deaths in the overall view.

Age-group comparisons

Charts compare outcome counts and selected indicator averages across the displayed age bands: Below 40, 40–50, 51–60, 61–70 and 71+.

Gender selection

Male and Female buttons change the dashboard context, with separate screenshots showing the corresponding filtered values and charts.

Health-related indicators

The report visualizes ejection fraction and serum creatinine alongside age-group outcome counts, and includes a comparison of smoking, high blood pressure, diabetes and anaemia.

04 — DASHBOARD & ANALYTICAL DESIGN

Keep the key outcome measures visible while supporting focused comparisons.

The dashboard combines a compact KPI column with age-group charts and gender controls. The layout is designed for visual exploration of the measures included in the report.

At-a-glance KPI summary

Average survival age, survival rate, total survivor count and total death count provide the high-level summary displayed in the report.

Age-group analysis

Column and line visuals compare outcome counts with average ejection fraction and average serum creatinine across the five age bands shown in the dashboard.

Survival-rate comparison

An area-style chart displays survival rate by age group, allowing users to inspect how the displayed rate varies between age bands.

Risk-indicator comparison

A ribbon-style visual brings together smoking, high blood pressure, diabetes and anaemia indicators by age group for side-by-side exploration.

DESIGN PRINCIPLE

Make the overall outcome summary easy to scan, then let users examine age-group and gender-filtered views without presenting dashboard associations as medical conclusions.

07 — EVIDENCE & PROJECT SCOPE

Describe the dashboard evidence without overstating what the report can establish.

This case study distinguishes the values and features visible in the published screenshots from implementation details that are not documented in the repository.

Overall dashboard values

The portfolio overview screenshot displays an average survival age of 58.76, survival rate of 67.89%, 203 total survivors and 96 total deaths.

Gender-filtered evidence

The Male screenshot displays 132 survivors and 62 deaths, while the Female screenshot displays 71 survivors and 34 deaths. These are dashboard values shown under the respective gender selections.

Repository artifacts

The public repository contains the Power BI dashboard file, README and four PNG images: one portfolio overview and three dashboard screenshots (overall, male-filtered and female-filtered).

Documentation boundary

The repository README currently contains only a project title and a brief description. Dataset provenance, transformation steps, data-model relationships and measure definitions are not documented there, so this case study does not claim a specific data-preparation pipeline or DAX implementation.

Scope note: the figures are rounded/displayed values visible in the repository screenshots, not independently re-audited calculations. The dashboard is an exploratory analytics artifact and should not be interpreted as a clinical diagnostic or causal model.
