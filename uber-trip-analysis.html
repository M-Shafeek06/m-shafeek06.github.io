02 — ANALYTICAL CONTEXT & OBJECTIVE

Bring booking, vehicle, location and time patterns into one report.

The dashboard presents multiple views of trip activity so a user can move from high-level indicators to time patterns and individual trip records.

THE ANALYTICAL NEED

Trip performance has several dimensions.

Booking volume and booking value provide a high-level view, while vehicle category, pickup and drop-off locations, payment type and pickup time add context to the trip activity represented in the report.

THE PROJECT OBJECTIVE

Create an interactive trip-analysis report.

The project brings together an overview page, a time-analysis page and a details page. The report includes date and city filtering, selectable metric views and a trip-level table for closer inspection.

03 — REPORT STRUCTURE

A report organized around three connected analytical views.

The public project repository provides the Power BI report file and screenshots of its three pages. The structure below describes the visible reporting experience rather than claiming an undocumented data-engineering pipeline.

Report entry & filters

The report interface displays a date range and city selector, allowing the visible report to be explored in a selected context.

Overview Analysis

A summary page combines booking and trip KPIs with payment, day/night, vehicle and location views.

Time Analysis

A time-focused page presents bookings by pickup time, day name and hour-by-day matrix.

Details

A tabular page exposes trip-level fields such as trip ID, pickup date and hour, vehicle, payment type, passenger count, distance, booking value and location.

04 — REPORT & ANALYTICAL DESIGN

Use separate views to answer different trip-analysis questions.

The visible report design moves from summary indicators to temporal patterns and then to detailed records, with shared report controls and a consistent page-navigation pattern.

Executive overview

KPI cards summarize total bookings, total booking amount, average booking value, total trip distance, average trip distance and average trip time.

Vehicle & location comparison

The overview includes a vehicle comparison table, frequent pickup and drop-off point cards, booking counts by location and preferred vehicle by pickup location.

Time-pattern exploration

The time page uses a pickup-time chart, day-name comparison and an hour-by-day matrix to make temporal variation easier to inspect.

Record-level inspection

The Details page presents a scrollable table of trip records and their associated booking attributes.

DESIGN PRINCIPLE

Move from summary to pattern to record-level detail, keeping each report page focused on a distinct analytical question.

06 — REPORT CAPABILITIES

Explore trip activity through the views visible in the dashboard.

The capabilities below are grounded in the three published dashboard screenshots and the project file available in the repository.

Booking & trip KPIs

Display total bookings, total booking amount, average booking value, total and average trip distance, and average trip time.

Payment & trip-type mix

Show booking amount by payment type and by day/night trip classification using donut-chart visuals.

Vehicle analysis

Compare vehicle categories across booking count, booking amount, average booking value and total trip distance.

Pickup & drop-off locations

Present frequent pickup and drop-off points, a farthest-trip callout, booking volume by location and preferred vehicle by pickup location.

Time-based booking patterns

Explore bookings by pickup time, bookings by day name and an hour-by-day matrix with an accompanying hourly summary.

Trip-level detail table

Inspect individual rows with trip ID, pickup date, pickup hour, vehicle, payment type, passenger count, trip distance, total booking, location and total bookings fields.

07 — EVIDENCE & PROJECT SCOPE

Keep the published evidence distinct from undocumented implementation details.

The case study reports what can be checked in the repository and the supplied dashboard screenshots. It does not infer a full data model or transformation pipeline from the visual output alone.

Visible reporting period

The dashboard screenshot shows a date filter from 01 June 2024 to 30 June 2024.

Displayed summary values

The overview screenshot displays approximately 103.7K bookings, $1.55M total booking amount, $14.98 average booking value, 349K miles total trip distance, 3 miles average trip distance and 16 minutes average trip time.

Repository artifacts

The public repository contains the Power BI report file, README and four PNG images: one portfolio overview image and three report-page screenshots.

Documentation boundary

The repository README currently provides only a brief project description. Detailed dataset provenance, transformation steps, model relationships and measure definitions are not documented there, so this page does not make claims about those implementation details.

Scope note: the KPI values above are rounded values visible in the report screenshot. They are presented as dashboard display values, not as independently re-audited calculations or measured business outcomes.
