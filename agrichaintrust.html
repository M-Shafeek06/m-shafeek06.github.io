02 — PROJECT CONTEXT & OBJECTIVE

Make agricultural product information easier to trace and verify.

Agricultural supply chains can involve multiple participants and hand-offs. AgriChainTrust explores a digital product experience that supports traceability and verification, with frontend and backend components organized as separate codebases.

THE PROBLEM SPACE

Supply-chain information can be fragmented.

When product details and movement records are distributed across different participants, it can be difficult for downstream users to inspect a consistent product history. The project is framed around making product-related information more accessible through a digital interface.

PROJECT OBJECTIVE

Connect a user-facing experience with verification-oriented services.

The project separates the React/Vite frontend from the Node.js backend and explores QR-based product access alongside blockchain-oriented verification components. The public repositories provide the implementation evidence for these technical layers.

03 — APPLICATION ARCHITECTURE

A separate frontend and backend, with verification-related integrations.

The architecture below reflects the repository boundaries and dependencies visible in the public codebases. It describes the documented application structure without implying that every integration is operating on a production blockchain network.

Frontend application

The frontend repository uses React 19 and Vite 7. Its dependencies include Axios, React Router, QR scanning and generation libraries, Leaflet mapping components, and charting packages.

Backend application

The backend repository uses Node.js with Express and Mongoose. Its package dependencies also include authentication utilities, ethers.js, an IPFS HTTP client, QR generation, geocoding and logistic-regression libraries.

Verification-oriented components

The backend dependency manifest includes ethers.js and an IPFS client, while the frontend includes QR scanning and generation packages. These are documented as integration capabilities in the codebase, not as proof of a live on-chain production workflow.

04 — PRODUCT & TECHNICAL DESIGN

Keep the product experience and service responsibilities distinct.

The design is best understood through the separation of user interaction, API communication and backend capabilities. This makes the project structure easier to inspect and evolve.

Frontend-led interaction

React and Vite provide the browser application foundation. React Router supports client-side navigation, while Axios is available for communication with backend services.

QR-enabled access

The frontend dependency list includes html5-qrcode, jsqr and qrcode.react, indicating QR scanning and QR-code rendering support within the application toolkit.

Location and visual components

Leaflet and React Leaflet are included for map-oriented interface components. Chart.js, react-chartjs-2 and Recharts are available for visual presentation.

Backend integration layer

The backend repository groups application source, middleware, scripts and assets. Its dependencies indicate API, persistence, authentication and verification-related integration areas.

07 — RELIABILITY & PROJECT SCOPE

Separate verified repository evidence from intended product behaviour.

A credible technical case study should distinguish visible implementation evidence from broader product goals. This page deliberately avoids presenting dependency names as proof of complete integrations.

Repository evidence

The frontend repository exposes its package manifest, React/Vite project structure and Vercel deployment link. The backend repository exposes its package manifest and directories for source, middleware, scripts and assets.

Integration boundary

Dependencies such as ethers.js, IPFS client, QR libraries and Mongoose show the technical tools included in the codebases. They should not be interpreted as independent confirmation of a live blockchain network or production-grade persistence.

Documentation limitation

The frontend README currently retains the default React/Vite starter documentation, and the repositories do not provide a consolidated product-level technical guide. Detailed feature behaviour therefore remains limited to what can be directly inspected.

Portfolio positioning

AgriChainTrust demonstrates software-development breadth alongside the analytics portfolio. It is presented as a technical application project rather than a core data-analysis case study.
