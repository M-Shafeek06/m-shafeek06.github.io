SYSTEM DESIGN

Architecture behind the workflow.

The architecture separates the web interface, API routing, data profiling, quality assessment and analytical services.

01 — THE OBJECTIVE

Make structured analysis easier to execute and explain.

Problem addressed

Users often need to inspect a dataset, identify data-quality concerns, choose appropriate analyses, interpret results and communicate findings across separate steps and tools.

Project objective

InsightForge AI brings dataset profiling, deterministic data-quality checks, supported analytical operations, charts and business-oriented interpretation into one web application.

02 — CORE WORKFLOW

Understand → Clean → Analyze → Visualize → Explain → Decide.

The implemented MVP focuses on understanding uploaded data, assessing quality, executing supported analysis and presenting evidence-based results.

03 — IMPLEMENTED CAPABILITIES

Functional analytics, not just a dashboard mockup.

Dataset ingestion & profiling

Upload CSV and Excel datasets, inspect dataset dimensions and column information, and review data types, semantic roles, missing values and profiling results.

Data-quality assessment

Detect missing values, duplicate rows, empty and constant columns, date-like text, invalid dates and high-cardinality columns; display severity classifications and recommended actions.

Analytical operations

Run KPI aggregations, descriptive statistics, time-based trend analysis, segment comparisons and Pearson correlation for numerical relationships.

Visualizations & business insights

Present analytical results in charts and tables, with interpretations tied to calculated observations, data-quality limitations and suggested follow-up questions.

Business Analysis Planner

Submit a business objective and receive suggested KPIs, analytical approaches, relevant dataset columns and data-quality warnings. Planner recommendations are kept distinct from executed calculations.

Multiple-dataset validation

The deployed MVP has been manually exercised across multiple datasets, including small sample data and larger retail datasets, according to the project documentation.

FEATURE PREVIEWS

From dataset context to quality checks.

04 — TECHNOLOGY & ARCHITECTURE

A separate frontend and analytical backend.

Frontend

Next.js 16, React 19, TypeScript, Tailwind CSS 4 and Plotly support the web interface and analytical visualizations.

Backend & data processing

Python 3.12, FastAPI and Pydantic handle API and validation responsibilities; Pandas, PyArrow and DuckDB support data processing and analytics.

Persistence & infrastructure

The documented stack includes PostgreSQL, SQLAlchemy, the psycopg driver and Docker Compose infrastructure.

Deployment

The frontend is deployed on Vercel and the backend API on Render. Public links are provided above for direct review.

05 — ANALYTICAL RELIABILITY

Keep recommendations separate from calculated results.

Deterministic calculations

Implemented analytical operations use deterministic data-processing logic. The Business Analysis Planner proposes approaches; it does not represent those proposals as completed calculations.

Responsible interpretation

Correlation is treated as association rather than causation. Small datasets and data-quality limitations are acknowledged when interpreting findings.

This case study describes the implemented MVP scope documented in the public repository. It does not claim that future roadmap features are already available.
