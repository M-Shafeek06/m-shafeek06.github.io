02 — BUSINESS CONTEXT & OBJECTIVE

Connect the steps between receiving a dataset and making sense of its results.

The project focuses on a common analytics challenge: the work required before a chart or KPI can be trusted and communicated clearly.

THE CHALLENGE

Analysis can become fragmented.

Working with an unfamiliar dataset often means switching between tools to inspect its structure, locate quality issues, decide which analysis is appropriate, execute calculations and explain the output. When these steps are disconnected, it is harder to maintain a clear line from source data to business interpretation.

THE OBJECTIVE

Build one guided analytics workflow.

InsightForge AI brings dataset profiling, deterministic quality assessment, cleaning support, business analysis planning, analytical execution, interactive visualizations and AI-assisted interpretation into one application. The goal is to make each stage visible and help users understand how an output was produced.

03 — SYSTEM ARCHITECTURE

A separated frontend and backend, connected through clear API boundaries.

The frontend handles the user experience and communicates with backend services through API requests. The backend coordinates validation, data processing, analytical operations, persistence and AI-assisted interpretation.

Frontend layer

Next.js, React and TypeScript deliver the application interface, while Plotly presents interactive analytical visualizations.

API & processing layer

Python, FastAPI and Pydantic handle API and validation responsibilities. Pandas, NumPy and DuckDB support data processing and analytical execution.

Persistence layer

PostgreSQL stores application records, with SQLAlchemy and the PostgreSQL driver supporting database operations.

Deployment layer

The public frontend is deployed on Vercel and the backend API is hosted on Render, with managed PostgreSQL provided through Neon.

04 — PRODUCT & ANALYTICS DESIGN

Make the analytical process understandable, not just the final chart.

The product is organized around a sequence of analyst tasks. Each stage gives users a clearer view of the dataset, the checks performed and the analytical options available before they interpret the result.

Dataset-first experience

Start with file structure, dimensions, column types, semantic classifications and missing-value information so the user can understand the data before selecting an analysis.

Visible quality assessment

Surface data-quality issues as explicit findings, with severity and context, instead of hiding data limitations behind a dashboard.

Analysis tied to the question

The Business Analysis Planner translates a stated business objective into suggested KPIs, relevant columns and analytical approaches. Suggestions remain distinct from calculations that have actually been executed.

Results with context

Present results through KPI summaries, charts and tables, alongside explanations that remain grounded in the executed analysis and its limitations.

DESIGN PRINCIPLE

Show what the data says, make the analytical steps visible, and distinguish calculated results from suggested next steps.

06 — IMPLEMENTED CAPABILITIES

Functional capabilities across the analytics lifecycle.

The following capabilities are documented in the public project repository and implemented in the deployed MVP.

Dataset ingestion & profiling

Upload CSV and Excel workbooks, select worksheets where applicable, inspect dataset dimensions and review column types, semantic classifications, missing values and profiling information.

Deterministic data-quality checks

Assess missing values, duplicate rows, empty columns, constant columns, date-like text, invalid dates and high-cardinality columns, with findings categorized by severity.

Cleaning & dataset versions

Review supported cleaning recommendations, apply transformations and work with generated dataset versions to keep cleaning actions visible in the workflow.

Business Analysis Planner

Translate business objectives into suggested KPIs, relevant columns, analytical operations, data-quality considerations and clarification questions.

Analytical execution

Run KPI and aggregation analysis, descriptive statistics, time-based trends, segment comparisons and correlation analysis on supported numerical variables.

Visuals, insights & reports

Explore KPI outputs, trend charts, segment comparisons and correlation visuals; save selected analyses and generate downloadable PDF reports.

07 — RELIABILITY & ENGINEERING

Prefer verifiable calculations and make limitations explicit.

A decision-support tool needs more than attractive visuals. Its analytical outputs should be traceable to calculations, and its limitations should be clear to the person using them.

Deterministic analysis

Supported analytical operations use data-processing logic to calculate results. AI-assisted interpretation is a separate layer and does not replace the underlying calculations.

Validation before interpretation

Data-quality checks surface issues such as missing values, duplicates and invalid dates before users rely on downstream analysis.

Testing evidence

The repository README records a backend test run of 243 passed with 1 dependency deprecation warning (November 20, 2026).

Known limitations

Results depend on dataset suitability and quality. Correlation does not establish causation, AI-generated interpretations require review, and the current Render free-tier filesystem is ephemeral.

Scope note: InsightForge AI is presented as a deployed MVP. This case study does not claim enterprise-scale infrastructure, guaranteed AI accuracy or independently measured business impact.
